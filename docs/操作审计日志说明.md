# 操作审计日志

记录“谁在什么时间、从哪里、对哪个接口做了什么、结果如何”，用于安全排查与操作追溯。
采集由中间件完成，业务 Controller 无需改动；写入异步化，审计失败不影响主请求。

## 表结构

表名 `AuditLog`（继承 `BaseEntity`，`CreateTime` 即对外 `CreatedAt`）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `Id` | BIGINT | 主键（雪花 Id）；JSON 中输出为字符串 |
| `UserId` | BIGINT NULL | 操作用户 Id；未认证为 null；JSON 中输出为字符串 |
| `UserName` | VARCHAR(100) | 操作用户名；未认证为 `anonymous` |
| `HttpMethod` | VARCHAR(10) | HTTP 方法 |
| `Path` | VARCHAR(500) | 请求路径（不含查询串） |
| `QueryString` | VARCHAR(1024) | 查询串（已脱敏、截断） |
| `RequestBody` | VARCHAR(2048) | 请求体（已脱敏、截断） |
| `StatusCode` | INT | HTTP 状态码 |
| `ResultCode` | INT NULL | 业务结果码，优先取统一结果；业务失败可能 HTTP 200 但为 4xx |
| `Succeeded` | TINYINT(1) | 业务是否成功；无统一结果时为状态码 < 400 且未抛出异常 |
| `ClientIp` | VARCHAR(64) | `X-Forwarded-For` 首值，兜底 `RemoteIpAddress` |
| `UserAgent` | VARCHAR(500) | 客户端 UA（截断） |
| `TraceId` | VARCHAR(128) | 与响应头 `x-request-id`、文件日志同源 |
| `DurationMs` | BIGINT | 请求耗时（毫秒） |
| `ExceptionMessage` | VARCHAR(1024) | 未处理异常消息（已脱敏、截断） |
| `SqlCount` | INT | 本次请求执行的 SQL 条数（含未记录明细的快速 SQL） |
| `SqlElapsedMs` | BIGINT | 本次请求 SQL 净耗时合计（毫秒） |
| `SlowSqlCount` | INT | 本次请求超过慢阈值的 SQL 条数 |

索引：`IX_AuditLog_CreateTime`、`IX_AuditLog_UserId`、`IX_AuditLog_Path`。

### SQL 明细表 `AuditSqlLog`

与 `AuditLog` 一请求对多记录（无外键，清理时显式级联删除），同样继承 `BaseEntity`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `Id` | BIGINT | 主键（雪花 Id）；JSON 中输出为字符串 |
| `AuditLogId` | BIGINT | 所属审计记录 Id |
| `TraceId` | VARCHAR(128) | 请求链路 Id，与 `AuditLog.TraceId` 一致 |
| `SqlText` | VARCHAR(2000) | SQL 文本（已脱敏、截断） |
| `Parameters` | VARCHAR(2000) NULL | 参数键值对（敏感参数值掩码，整体截断） |
| `ElapsedMs` | BIGINT | 单条 SQL 净耗时（毫秒） |
| `IsSlow` | TINYINT(1) | 是否达到慢阈值 |
| `ErrorMessage` | VARCHAR(1000) NULL | 执行失败原因（已脱敏、截断）；成功为 null |
| `CreateTime` | DATETIME | 创建时间（对外 `CreatedAt`） |

索引：`IX_AuditSqlLog_AuditLogId`、`IX_AuditSqlLog_TraceId`、`IX_AuditSqlLog_CreateTime`。

> `Id`/`UserId`/`DurationMs` 等 `long` 字段统一序列化为 JSON 字符串（全局 long 转换器），
> 避免雪花 Id 超过 JS `Number.MAX_SAFE_INTEGER` 后前端丢精度。

## 接口（均要求 Admin）

Furion 动态 API，路由前缀 `/Api/AuditLog`，实际谓词以服务端路由为准。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/Api/AuditLog/GetAuditLogList` | 分页列表：`StartTime`、`EndTime`、`UserId`、`UserName`、`Path`、`Succeeded`、`HttpMethod`、`PageIndex`、`PageSize` |
| GET | `/Api/AuditLog/GetAuditLogDetail?id=` | 详情（含已脱敏请求体与该请求的 SQL 明细 `SqlLogs`） |
| GET | `/Api/AuditLog/GetSlowSqlList` | 慢 SQL 列表：`StartTime`、`EndTime`、`MinElapsedMs`（默认 200）、`PageIndex`、`PageSize`；附带所属请求的 `UserName/Path/HttpMethod` |
| POST | `/Api/AuditLog/CleanupAuditLogs?retentionDays=` | 手动清理：删除 N 天前记录（默认 90，范围 1-3650），返回删除条数（明细同步删除） |

普通用户（非 Admin）访问返回 403；未登录返回 401。列表返回 `SqlCount/SqlElapsedMs/SlowSqlCount`；详情与慢 SQL 列表中的 SQL 文本、参数、失败原因均在采集阶段脱敏，不存在明文密码/令牌。

## 采集策略

- **记录范围**：默认只记录 `POST/PUT/PATCH/DELETE` 与登录类接口（`/Login`、`/Register`、`/Refresh`、`/Logout`）；GET 默认不生成审计记录，但开启 `AuditLog.Sql.AuditSlowGet`（默认 `true`）时，出现慢 SQL 的 GET 会补一条审计记录以便追溯慢查询；`AuditLog.IncludeGet=true` 则所有 GET 全量记录。
- **跳过**：`/health`、静态文件、审计查询接口自身（`SkipPaths` 前缀匹配），避免自我放大。
- **请求体**：`EnableBuffering` 重复读取，业务模型绑定不受影响；最多读取 `MaxBodyLength × 4` 字符，脱敏后再按 `MaxBodyLength` 截断（默认 2048）。
- **脱敏**：JSON 按字段递归掩码，非 JSON 走正则兜底；完整键名匹配 `password/pwd/passwd`、`accessToken`、`refreshToken`、`authorization`、`secret`、`token`，验证码语义键匹配 `code`、`verifyCode`、`verificationCode`、`captchaCode`、`smsCode`、`emailCode`、`mobileCode`、`otpCode`（忽略大小写与下划线）；`permissionCode`、`roleCode`、`orderCode` 等业务编码保留原值，值统一替换为 `***`。
- **身份**：中间件位于认证之后、授权之前，未认证的 401、角色不足的 403、吊销令牌的 401 都会被记录。
- **失败处理**：请求线程只做一次非阻塞入队；后台服务批量写入。队列满丢弃新记录并记 Warning；写库失败仅记 Error，不影响业务响应。
- **性能**：排队与批量写入避免请求线程等待数据库；典型单条写入开销在请求总耗时中可忽略。

### SQL 执行明细采集

- **采集方式**：SqlSugar AOP（`OnLogExecuted` / `OnError`）在语句执行后读取净耗时，只向当前请求的 `HttpContext.Items` 缓冲区追加数据，不访问数据库、不抛异常。
- **默认记录范围**：只记录达到慢阈值（`SlowThresholdMs`，默认 500ms）的 SQL，以及执行失败的 SQL（不依赖阈值，附带 `ErrorMessage`）。正常且不慢的 SQL 只计入 `SqlCount`，不产生明细。默认 500ms 是为了避开 NAS 上常规写菜单 220-300ms 的抖动；排查时可临时调低（如 100ms）。
- **慢 GET 入审计**：`AuditLog.Sql.AuditSlowGet` 默认 `true`。GET 请求默认不生成审计主记录，但当请求内出现达到慢阈值的 SQL 时，补一条审计记录（`Succeeded/ResultCode` 按请求实际结果），并在详情中返回慢 SQL 明细；正常 GET 仍无审计记录。设为 `false` 则恢复“GET 完全不记录”。该开关仅在 `Sql.Enabled=true` 时生效。
- **全量排查开关**：`AuditLog.Sql.RecordAll=true` 时记录请求内全部 SQL，用于临时排查接口，修改配置重启即生效，无需发版；排查完应改回 `false`。探测型 GET（仅因慢 SQL 补记录）始终只保留慢/失败明细，避免全量格式化无效数据。
- **请求关联**：缓冲区挂在当前请求的 `HttpContext.Items` 上，请求结束立即关闭。同一请求内多条 SQL 归入同一条审计记录；不同请求各自独立。后台任务、定时任务无 `HttpContext`，或请求结束后仍在运行的异步任务，都会被跳过，不会串到其他审计记录。
- **脱敏与体积**：SQL 文本与参数分别截断（默认 2000 字符）；参数名为 `password/pwd/passwd/accessToken/refreshToken/token/secret/authorization` 或验证码语义键（`code/verifyCode/verificationCode/captchaCode/smsCode/emailCode/mobileCode/otpCode`，兼容下划线）时直接掩码参数值；`permissionCode/roleCode/orderCode` 等业务编码保留原值；单条审计记录最多保留 50 条明细，超出部分追加“已截断”标记。
- **失败 SQL 取舍**：`OnError` 回调中的参数以 SqlSugar 异常对象提供的运行时结构为准；能解析出参数数组时正常脱敏记录，否则仍记录 SQL 文本与失败原因。
- **性能影响**：AOP 只做内存追加与字符串截断，单条开销为微秒级；明细随审计主记录一起在后台批量落库，按 200 条分块写入。开启 `RecordAll` 或把阈值调得很低会显著增加明细量。

## 配置（applicationsettings.json → `AuditLog`）

```json
{
  "AuditLog": {
    "Enabled": true,
    "IncludeGet": false,
    "RecordLoginEndpoints": true,
    "RecordRequestBody": true,
    "MaxBodyLength": 2048,
    "MaxQueryStringLength": 1024,
    "MaxExceptionLength": 1024,
    "SkipPaths": [ "/health", "/Api/AuditLog", "/swagger", "/api-docs" ],
    "QueueCapacity": 10000,
    "RetentionDays": 90,
    "CleanupHour": 3,
    "Sql": {
      "Enabled": true,
      "RecordAll": false,
      "SlowThresholdMs": 500,
      "AuditSlowGet": true,
      "MaxSqlLength": 2000,
      "MaxParametersLength": 2000,
      "MaxItemsPerAuditLog": 50
    }
  }
}
```

## 保留与清理

- 每日清理任务在本地时间 `CleanupHour`（默认 3 点）执行一次，物理删除 `CreateTime` 早于 `RetentionDays` 的审计记录；重启不会额外多跑。
- SQL 明细与审计记录同生命周期：清理时先按过期审计 Id 分块删除 `AuditSqlLog`，再删主记录，避免孤儿明细。
- 与现有 `IDeleteDirJob`（60 秒周期、只清理临时文件）独立，不会每分钟扫描审计表。
- 管理端 `CleanupAuditLogs` 提供同样的幂等手动入口，便于临时回收空间。

## 建表与部署

- 全新环境：应用启动时 `DatabaseInitializer` 通过 CodeFirst 建表并创建索引。
- 存量库：先执行 `Sql/2026-11-04_AuditLog表与索引.sql`，再执行 `Sql/2026-11-04_AuditSqlLog明细表与汇总列.sql`（两者均幂等，可重复执行；已存在表/列/索引时自动跳过）。
  CodeFirst 启动时也会同步缺失的 `SqlCount/SqlElapsedMs/SlowSqlCount` 列与 `AuditSqlLog` 表，脚本用于无法自动迁移的场景兜底。

```bash
mysql -h <主机> -u <账号> -p LogicNet < Sql/2026-11-04_AuditLog表与索引.sql
mysql -h <主机> -u <账号> -p LogicNet < Sql/2026-11-04_AuditSqlLog明细表与汇总列.sql
```

内置 MySQL 模式：

```bash
docker compose -f docker-compose.yml -f docker-compose.mysql.yml exec mysql \
  sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" logicnet' < "Sql/2026-11-04_AuditLog表与索引.sql"
```
