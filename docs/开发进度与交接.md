# 开发进度与交接说明

本文件用于换机器继续开发时快速恢复上下文：仓库位置、启动方式、已完成功能、接口约定与待办。
更细的专题文档见 `docs/Menu维护接口说明.md`、`docs/操作审计日志说明.md`、`DEPLOY.md`。

## 一、仓库与分支

| 部分 | 仓库 / 分支 | 本地目录 | 技术栈 |
| --- | --- | --- | --- |
| 后端 | `git@github.com:quliting/LogicNet.git`，`main` | 仓库根目录 | .NET 9 + Furion 4 + SqlSugar + MySQL 8 |
| 前端 | 同一仓库的 `front` 分支（单次快照提交） | `Front/`（已被后端 `.gitignore` 排除） | vben 5.8 `apps/web-ele`：Vue 3.5 + Vite + TS + Element Plus |

前端原本是 vben 官方仓库的克隆（origin 指向 `vbenjs/vue-vben-admin`，无法推），因此改为把工作区快照推到 LogicNet 的 `front` 分支。
本地 `Front/` 仍保留自己的 git（本地 `main` 上有一个业务提交 `feat: 对接 LogicNet 后端登录、动态菜单与菜单管理`，remote `logicnet` 指向 LogicNet 仓库）。
**改动前端后需要重新导出快照并推送 `front` 分支**，否则另一台机器看不到最新前端代码（做法见第五节）。

## 二、换电脑后如何继续

```bash
# 1) 后端
git clone git@github.com:quliting/LogicNet.git
cd LogicNet
cp secrets.json.example <输出目录>/secrets.json   # 填真实 JWT 密钥与 MySQL 连接串，切勿提交
dotnet build LogicNet.sln
dotnet run --project LogicNet.Web.Entry            # 默认 8080，探活：GET /health
```

```bash
# 2) 前端（取 front 分支到独立目录，避免污染后端工作区）
git clone -b front git@github.com:quliting/LogicNet.git LogicNet-Front
cd LogicNet-Front && pnpm install
# 修改 apps/web-ele/.env.development 的 VITE_GLOB_API_URL 指向后端，例如 http://<后端IP>:8080/Api
pnpm dev:ele                                        # 默认 5777
```

- 后端机密（JWT 密钥、数据库连接串）只走 `secrets.json`（Furion 扫描输出目录 `*.json`），进程环境变量不生效，见 `DEPLOY.md`。
- 测试账号：`lnadmin01` / `LnAdmin2026`（Admin 角色，已存在于 NAS 数据库；代码里不预置管理员用户）。
- 登录必须先取图形验证码（`/Api/Captcha/GetCaptcha` 返回 `Url` + `Key`），校验成功后验证码一次性销毁；同一验证码错误尝试上限 5 次。
- 容器化部署：`deploy.sh` / `scripts/update.sh`（NAS 构建需关闭 BuildKit）。

## 三、已完成功能（按模块）

### 1. 认证与安全基线

- 全局默认要求认证，仅登录、注册、刷新令牌、验证码接口匿名；授权异常返回规范 401/403，不再 500。
- 密码 PBKDF2-SHA256 加盐哈希，存量无盐 MD5 在登录时透明迁移（`PasswordHasher`）。
- 令牌刷新用 Furion 原生 Exchange：访问令牌在响应体 `Data`，轮换后的刷新令牌走响应头 `x-access-token`。
- 验证码、登录、注册等高风接口使用框架原生限流；分页 `PageSize` 钳制 1–100。
- 用户列表手机号脱敏；`TestService` 等调试接口已加鉴权。
- 软删除用户由全局过滤器排除（不可查询、不可登录）。

### 2. 菜单与角色菜单（最近一轮重点）

- 菜单实体支持目录/菜单/按钮三级类型，`(ParentId, Path)` 唯一索引，软删除，父子防环。
- 接口（`/Api/Menu`）：`CreateMenu`、`UpdateMenu`、`DeleteMenu`、`GetMenuDetail`、`GetMenuList`、`GetMenuTree`（Admin）、`GetMyMenus`（登录）。
- 删除策略：仍有子节点时拒绝并返回可读提示，需自底向上删除。
- 角色菜单绑定（`/Api/RoleMenu`）：`GetRoleMenus`、`SaveRoleMenus`（Admin），`MenuIds` 为最终勾选集合；父子联动在服务端完成（勾子级自动补祖先，取消父级连带整棵子树）。
- Admin 角色无需绑定，`GetMyMenus` 兜底返回全量；普通角色按 `RoleMenu` 收窄，逻辑集中在 `MenuService.ApplyRoleFilter`。
- 角色列表 `/Api/Role/GetRoleList`（Admin）供授权选择。
- 细节与字段约定见 `docs/Menu维护接口说明.md`。

### 3. 操作审计日志

- 中间件采集（不侵入 Controller），请求体 `EnableBuffering`、截断 2KB，敏感字段掩码（password/token/authorization/验证码语义键等）。
- 写入异步批量、失败仅记录 Error 不阻塞主请求；`CreatedAt`、`UserId`、`Path` 建索引；每日清理任务默认保留 90 天。
- SQL 明细采集（SqlSugar AOP）：默认慢 SQL 阈值 500ms，可配 `AuditLog.Sql.SlowThresholdMs`；GET 请求默认不产生主记录，仅当出现慢 SQL 时补记（`AuditLog.Sql.AuditSlowGet`）。
- 查询接口仅 Admin；`/health`、静态文件、审计查询自身跳过采集。
- 详见 `docs/操作审计日志说明.md`。

### 4. 基础设施

- 雪花 ID（Yitter）：固定 `BaseTime=2025-05-04`、`WorkerIdBitLength=10`、`SeqBitLength=6`；`WorkerId` 从 `IdGenerator:WorkerId` 读取，未配置按主机/容器标识推导并校验范围。
- 所有 `long`/雪花 Id 统一按 JSON 字符串输出（`LongToStringJsonConverter`），避免 JS 精度丢失；入参同时兼容字符串与数字。
- `/health` 健康检查含数据库连通性，供容器探活。
- 启动自动 CodeFirst 建表 + 角色种子（Admin/User）+ Admin 全量菜单绑定，脚本幂等。

### 5. 前端（`Front/`，`apps/web-ele`）

- 请求层适配 Furion 统一返回：`Code === 200 && Succeeded === true` 才成功，失败统一取 `Errors` 文案；`assertFurionSuccess` 供 `responseReturn: 'raw'` 场景显式校验。
- 登录页接入图形验证码（`captcha-input.vue` + `use-captcha.ts`），登录参数透传 `LoginType/Mobile/UserName/PassWord/Key/Code`。
- 开启后端菜单模式（`accessMode: 'backend'`），菜单来自 `GetMyMenus`；`enableRefreshToken` 已开启，刷新令牌读响应头。
- 菜单管理页 `src/views/system/menu/index.vue`：树表默认全展开、一键展开/折叠、筛选保留父级上下文、行内「添加子级」、按钮类型强制填权限码、删除二次确认与子节点拦截。
- 角色授权抽屉 `RoleMenuDrawer.vue`：选择角色 → 勾选菜单树 → 提交最终集合，父子联动由后端处理。
- ID 全程按字符串处理（`Id`/`ParentId`），不得转 Number。

## 四、前后端契约速查

- 统一返回：`{ Code, Data, Succeeded, Errors, Extras, Timestamp }`；**业务失败 HTTP 仍可能是 200**，必须读 `Code` / `Succeeded`。
- 鉴权失败才是 HTTP 401/403；401 触发刷新或重登，403 提示角色不足。
- 新访问令牌在 `Data`，新刷新令牌在响应头 `x-access-token`（CORS 需 expose 该头）。
- `GetMyMenus` 直接输出前端契约：`Id/ParentId` 字符串、`Type` 字符串枚举、`meta` 信息（title/icon/order/hide）。

## 五、前端快照更新方式（改完前端后）

```bash
cd Front
git add -A -- . ':!e2e-artifacts'
git commit -m "feat: ..."           # 本地 main 正常提交
git checkout --orphan front-tmp     # 生成新快照
git add -A -- . ':!e2e-artifacts' && git commit -m "chore: 前端快照"
git push logicnet front-tmp:front -f   # 仅覆盖快照分支，禁止强推 main
git checkout main && git branch -D front-tmp
```
